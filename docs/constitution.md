# Tsuri-threads 憲法

## 1. サイトの定義
Tsuri-threads.com は、釣り具・規格・釣り物・ライン・仕掛けの関係をたどれる接続型データベースである。

これはブログ主導サイトではない。レビュー主導サイトでもない。主役は接続である。

## 2. 主役
主役は entity 単体ではなく、relation / setup である。

優先される問いは次の通り。
- このリールは何に向くか
- この釣り物には何が必要か
- この条件ならどの番手帯か
- この条件の次に比較すべき候補は何か

## 3. 初期スコープ
最初は電動リール軸で始める。

初期フェーズでは次を優先する。
- 電動リール
- 釣り物
- PE条件
- 錘負荷条件
- 基本仕掛けカテゴリ
- 関連ページ導線

ロッド型番網羅や生活周辺カテゴリは後回しにする。

## 4. データ三層
データは次の三層で扱う。
- raw: 取得した事実の正本
- normalized: 比較しやすく整えた層
- derived: 一覧、比較、導線のための派生層

raw を正本とし、normalized / derived は再生成可能とする。

## 5. 正本
正本は GitHub repo に置く。
ローカルは作業コピーであり、正本ではない。

## 6. 責務分離
次を混ぜない。
- data
- UI
- relation logic
- content
- automation

1PR 1テーマを守る。

## 7. 公式値と経験則の分離
公式値と実用判断を混ぜない。
最低でも次を分ける。
- official_spec
- practical_range
- beginner_safe_range
- notes

## 8. UI導線
基本導線は次の順とする。
1. 魚種 / 条件
2. 必要番手帯
3. メーカー比較
4. 上位下位比較
5. setup

## 9. 実装順
トップページから作らない。
順番は次を基本とする。
1. 憲法
2. data schema
3. 少量サンプルデータ
4. 個別ページ
5. relation ページ
6. 条件ページ
7. トップページ

## 10. AIの役割
AIは実装補助者であり、設計責任者ではない。
アーキテクチャ、命名体系、責務境界、公開基準は人間が決める。

## 11. 自動化の優先順位
自動化は次を優先する。
- リンク死検知
- 差分検知
- 自動Issue化
- 内部リンク欠損検知
- 更新棚卸し

## 12. 禁止事項
- ブログ量産を主軸にしない
- entity ページだけを量産しない
- raw / normalized / derived を曖昧にしない
- docs 無しで実装を進めない
- 壊れた状態で前進しない

## 一文要約
Tsuri-threads は、釣り具・規格・釣り物の接続をたどれる DB サイトとして、電動リール軸から relation / setup 主導で構築する。
