# 最小消費原則

Tsuri-threads では、Cloud とトークン消費を抑えながら、構造確認と抽出精度を段階的に上げる。

## ルール
- まず少数サンプルで構造確認を行う。
- 同型が確認できるまで全件クロールを行わない。
- 新規ルール作成や例外解析を除き、AI による解釈を前提にしない。
- 実クロールはローカル環境で行い、クラウド側では既存成果物の整形・検証・比較を優先する。
- 1回の作業指示は最小差分で切り、確認・実装・検証を欲張りすぎない。
- 403 / 429 / 到達不能が連続した場合は即停止し、fixture またはローカル検証へ切り替える。

## 運用メモ
- broad crawl を急がず、sample-first で進める。
- 実サイトアクセスが必要な処理は crawler / runs 側に隔離し、repo を正本として保つ。
- AI は抽出本体ではなく、設計・例外判断・最小限の解釈に限定する。
