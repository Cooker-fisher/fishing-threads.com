## 改善タイプ別分析

### タイプ A: ラベル表記バリエーション（6件）

改善のほとんど（7件中6件）は「baseline 辞書が知らないラベル表記」が原因。  
これは辞書にエイリアスを追加すれば AI 不要で解決できる。

- `自重` → `自重(g)` のエイリアスを辞書に追加
- `最大ドラグ(kg)` → `最大ドラグ力(kg)` のエイリアスを辞書に追加
- etc.

**判断**: ラベルバリエーション起因の改善は AI で対処するのではなく  
**辞書の拡充**（`LABEL_DICT` へのエイリアス追加）で代替すべき。  
コスト対効果で辞書追加 >> LLM 呼び出し。

### タイプ B: スペック列が存在しない（1件）

308J の `spool_capacity_text` はスペック表に列がなく、  
description テキストから `PE3号-300m` を正規表現で回収した。

これは辞書では代替できない。ただし正規表現ベースの fallback rule でも実現可能。  
`評価スクリプト内の _SPOOL_FROM_DESC_RE` は LLM なしでこの 1 件を補完している。

**判断**: description fallback は正規表現で十分。AI を使う必要はない。

## 結論と推奨アクション

### AI補正は現時点では不要

今回の評価で発見した全 7 件の improvement は以下で代替可能：

1. **LABEL_DICT にエイリアス追加**（6件対応）  
   → `scripts/normalizers/electric_reel_minimal.py` の `LABEL_DICT` を拡充

2. **正規表現 fallback の追加**（1件対応）  
   → description から spool_capacity を抽出するルールを normalizer に組み込む

### AI補正が本当に必要になるシナリオ

- **ラベルが日本語の自由記述**（例: "本体の重さはどのくらいですか？" のような FAQ 形式）
- **複数ラベルにまたがる値**（例: スプール仕様が1セル内に「PE3号300m / PE4号230m」として混在）
- **異なるメーカーの非標準フォーマット**（エイリアスが100件規模に膨れ上がる場合）

上記のシナリオが確認されるまで、AI補正のコストを正当化できない。

### 次のステップ

1. `LABEL_DICT` に今回発見したエイリアス（`自重`, `最大ドラグ(kg)` 等）を追加
2. description fallback rule を normalizer に組み込む
3. ラベルカバレッジが 95%+ になったら AI補正の必要性を再評価する
4. 実サイトの HTML をサンプリングして辞書の穴を継続的に検出する
